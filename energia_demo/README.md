# Energia: офлайн-модель концепции

Это воспроизводимая демонстрация на Python 3.10+ без внешних зависимостей.
Она не подключается к оборудованию, сети, кошелькам или блокчейну.

Из корня репозитория:

```bash
python3 -m energia_demo
python3 -m unittest discover -s tests -v
```

Четыре условных владельца имеют по 1/4 доли. Каждый может зарегистрировать
устройство Type 1/2/3 и менять его виртуальное состояние. Подмена идентификатора
не предотвращена: проверка владельца демонстрирует правила модели, а не защищенную
аутентификацию. Перед реальным применением необходим отдельный проект безопасности.

Виртуальная медитация добавляет 1 условный кредит за минуту; это произвольное
правило интерфейса. Обмен переводит кредиты в учетный пул и добавляет demo ETH
по произвольному коэффициенту 0.001. Demo ETH нельзя вывести, передать или
обменять на Ethereum. Реальных выплат, доходности и рыночных котировок нет.

Проверяемые инварианты:

- Сумма четырех долей равна единице, доли не изменяются через API.
- Управлять чужим устройством и переоформлять устройство нельзя.
- Выпущенные кредиты = остатки владельцев + погашенные кредиты.
- Сумма demo ETH = погашенные кредиты × демонстрационный коэффициент.
- Ошибочные операции не изменяют остатки и журнал.

Эта модель не подтверждает заявления о квантовых вычислениях на катушках Тесла,
передаче энергии, распознавании биополя, регенерации клеток или лечебном эффекте.
Для связи с реальным устройством нужны его спецификация, протокол и результаты
измерений. Фиксированные доли в модели не устанавливают юридических прав.

## Декларативный язык проекта ARM

В концепции проекта ARM — система программирования катушек, sbela76 — алгоритм
последовательностей. Здесь реализован демонстрационный язык этой системы,
не ассемблер процессоров Arm.
Парсер действительно исполняет ограниченный набор инструкций в офлайн-модели.
Это не восстановленный язык существующего оборудования: исходные протоколы
оборудования и исходный закрытый код не предоставлены.

Пример файла `example.arm`:

```text
# Только виртуальные устройства
OWNER owner_a;
DEVICE coil_a TYPE 1;
DEVICE coil_b TYPE 3;
COMMAND coil_a activate;
COMMAND coil_b activate;
COMMAND coil_a deactivate;
```

```bash
python3 -m energia_demo.arm example.arm --owner owner_a
```

Каждая инструкция занимает отдельную строку; завершающая точка с запятой
необязательна. Пустые строки и строки комментария с `#` пропускаются.
Грамматика чувствительна к регистру:

```text
OWNER <owner_id>
DEVICE <device_id> TYPE <1|2|3>
COMMAND <device_id> <activate|deactivate>
```

Первая инструкция — ровно один `OWNER`. Допустимы `owner_a`, `owner_b`,
`owner_c`, `owner_d`; значение должно совпадать с отдельно переданным `--owner`.
Идентификатор устройства начинается с латинской буквы, далее допускает буквы,
цифры и `_`, общая длина до 64 символов. Лимиты исходника: 128 строк и 32768
символов. Циклы, выражения, команды ОС, Python и обращения к оборудованию
грамматикой не предусмотрены.

`deactivate` соответствует состоянию `sleep` внутренней модели. Чужие и
неизвестные устройства, повторная регистрация и некорректный синтаксис вызывают
ошибку. Функция `run(source, actor=..., simulation=...)` возвращает новую модель;
переданная исходная модель не изменяется, включая случай ошибки в конце файла.
Переданный владельцем идентификатор — только демонстрация разграничения прав,
он не заменяет реальную аутентификацию пользователя.
